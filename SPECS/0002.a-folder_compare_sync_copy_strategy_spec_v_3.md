# FolderCompareSync copy strategy — final spec (sparse, compression, pre‑alloc, verify)

> **Purpose.** One authoritative, side‑effect‑free decision process to pick the copy strategy per file, plus execution invariants and UI/UX guardrails. This spec removes knobs where they aren’t needed and standardises verification naming.

---

## 0) Design principles
- **Safety first:** never expand sparse data; block unsafe operations early.
- **Deterministic:** exactly one decision per file with a concise explainer line.
- **Side‑effect‑free preview:** no filesystem mutations during prechecks/preview.
- **Simple policy:** hard rules instead of user toggles (only size threshold remains).

---

## 1) Read‑only prechecks (fail fast; **no** mkdir here)
Run these prechecks **before** choosing a strategy.

1. **Sparse source?** (`FILE_ATTRIBUTE_SPARSE_FILE`)
   - -> **ABORT (skip) this file** do NOT proceed with choosing a copy strategy
   - Show modal **“Copy Refused — Sparse Source”** (OK only)
   - Return failure object **and** append a status line and a log line

2. **Paths / permissions / disk space / parent‑creatable?**
   - If any fails -> **ABORT** with specific, actionable message (also to status)

3. **Collect/Calculate flags (read‑only):**
   - `is_network`: either side is UNC / `DRIVE_REMOTE`
   - `src_is_compressed`: **file** attribute on source file reflects actual file compression
   - `tgt_dir_is_compressed`: **directory** attribute on target parent
   - `compression_intended = src_is_compressed or tgt_dir_is_compressed`
   - `target_fs_is_ntfs`: best‑effort (only used for pre‑alloc & FSCTL viability)

> **Notes:**    
> Actual **directory creation** happens later, only inside the chosen copier (below).    
> mkdir inside copier; STAGED attempt FSCTL on temp → continue uncompressed on failure; no pre-alloc for STAGED; pre-alloc only for DIRECT-LARGE on local NTFS.    

---

## 2) Policy invariants (always on)
- **Compressed --> STAGED** (even local<->local). 
- **Never use DIRECT strategies** when compression is in play on either side.
- **Never pre‑allocate target** in any copy Strategy when **compression is enabled/intended**.
- **Never pre‑allocate target over network** (if any side is network).
- **Pre-allocate may be attempted only for DIRECT-LARGE** (when local target is NTFS and not compressed).
  - given our decision matrix, STAGED is only chosen for network or compression—and both ban pre-allocation).
  - On pre-allocation API failure/unsupported -> **skip the pre-allocation** and log one concise info line (no abort, cleanup and continue attempting the copy)

---

## 3) Strategy selector (top‑down, after prechecks, refer to Decision matrix)
1. If **`is_network`** **or** **`compression_intended`** -> **STAGED** (chunked copy)
2. Else (local & not compressed):
   - `size ≤ threshold` -> **DIRECT‑SMALL** (Windows native CopyFileExW copy)
   - `size  > threshold` -> **DIRECT‑LARGE** (windowed mmap copy)

> **Notes:**    
> (is_network or compression_intended -> STAGED; else local -> DIRECT-SMALL/LARGE by size)    

---

## 4) Execution‑phase invariants (inside the chosen copier)
Applied just before actual I/O.

- **Ensure parent directory exists:** `mkdir(parents=True, exist_ok=True)` here (not during preview)
- **STAGED + compression_intended:**
  - Attempt `FSCTL_SET_COMPRESSION(COMPRESSION_FORMAT_DEFAULT)` on the **temp handle** **before** writing
  - If it fails (e.g., SMB or non‑NTFS), proceed **uncompressed** and log a single **override** line
  - **Never pre‑allocate** in any compression path
- **Pre‑allocation attempts** (only if allowed by policy):
  - **DIRECT‑LARGE** (local NTFS, not compressed) -> may pre‑alloc
  - **DIRECT‑SMALL** does not have a pre-allocate option
  - **STAGED** does not have a pre-allocate option
  - On failure/unsupported -> **skip** and log a concise info line
- **Verification (unified naming):**
  - **DIRECT‑SMALL:** `verify=mmap compare bytes` *(byte‑for‑byte compare via windowed mmap)*
  - **DIRECT‑LARGE:** `verify=hash on the fly` *(DEBUG: `hash(src:mmap)`)*
  - **STAGED:** `verify=hash on the fly` *(DEBUG: `hash(src:stream)`)*

## 5) UI / UX guardrails
- **Scan & re‑compare (attribute refresh):** 
  - On every scan/re‑compare ensure
    - Recompute
      - per‑side `is_sparse` (file attribute) 
      - UI compression intent flags (`src_is_compressed` from the **file** attribute; `tgt_dir_is_compressed` from the **target parent directory** attribute)
    - Rebuild the trees and **re‑apply tags/colors and selection guards** based on the new attributes, each time.
    - If a file is sparse then grey out and disable its checkbox and prevent it from being ticked by the user, and never allow its checkbox to become ticked during any (re)scan

### 5.1 Visual indicators (minimise Status column noise)
- **Compressed items (Explorer‑style):** render filenames in **blue** using Treeview **tags** (e.g., tag: `compressed`).
  - Files whose **file** attribute has `FILE_ATTRIBUTE_COMPRESSED` -> blue.
  - Folders whose **directory** attribute has `FILE_ATTRIBUTE_COMPRESSED` -> blue (*italic* style for folders only).
  - Add a small legend in some existing free area above the trees in blue: **“Blue = compressed”**.
- **Sparse sources:** render filenames in **red** using tag `sparse` (applied on the side that is sparse).
  - Add another small legend: **“Red = sparse (copy blocked)”** in red, next to the 'Blue = compressed' legend
- **Accessibility note:** ensure selected‑row foreground remains readable across themes; only if a theme overrides selection colors aggressively, fall back to adding a tiny glyph (🗜︎ for compressed) while keeping colors.

> **Notes:**
> Treeview tags—blue = compressed, red = sparse (copy blocked), legends, and selection guards (no ticking sparse)

### 5.2 Selection behavior
<!-- - **Sparse side copy selection is blocked:** clicking a checkbox on the sparse **source** side auto‑unticks itself and posts a toast/status line: *“Selection blocked: sparse source cannot be copied.”* -->
- **Sparse side copy selection is blocked:** a sparse file checkbox on the sparse **source** side must be greyed out and unable to become ticked by the user nor during any (re)scan
- **Smart parent ticking:** when ticking a folder, **skip sparse children** on the would‑be source side so that they aren’t auto‑selected.
- **Delete Orphans:** allowed; sparse status does **not** prevent selecting items in the Delete Orphans dialog.

### 5.3 Status/preview integration
- **Status column stays relatively clean**; no added text for compression/sparse beyond the color cues. (Existing messages for Same/Different etc remain.)
- **Preview Decisions table:** colors mirror the tree (blue for compressed, red for sparse). Rows that are sparse show **ABORT no copy** in Strategy and a note *“blocked: sparse source”*.

### 5.4 Refresh after operations or when sources are selected [ or re-selected ] and (re)Compared
- After a **real copy** or **Delete Orphans** operation that changed files, triggers the standard refresh **re‑scan both roots from disk, rebuild trees, re‑compare, and re‑apply color tags and selection guards** so the UI reflects on‑disk truth.
- After one or more sources are (re)selected since the user may have changed underlying files, the Compare button triggers the standard refresh **re‑scan both roots from disk, rebuild trees, re‑compare, and re‑apply color tags and selection guards** so the UI reflects on‑disk truth.
  - check that this is current behaviour and if not then change it so that it is

## 6) Decision matrix (first match wins)
*(Assumes prechecks already ran and didn’t abort.)*

| Condition | Strategy | Verify | Pre‑alloc attempt? | Notes / Explainer |
|---|---|---|---|---|
| **Sparse source** (caught in prechecks) | **ABORT** | — | — | Modal shown; status + failure return (`abort: SPARSE source detected`) |
| **`is_network = True`** | **STAGED** *(chunked copy)* | **hash** *(on the fly)* | **No** *(never over network)* | `decision: STAGED (network)`; if compression intended & target NTFS, try FSCTL; on failure: `override: proceeding uncompressed` |
| **Local & `compression_intended = True`** (src file compressed **or** target dir compressed) | **STAGED** *(chunked copy)* | **hash** *(on the fly)* | **No** *(never in compression path)* | `decision: STAGED (target‑compress/src‑compress)`; attempt FSCTL on temp; on failure: override line |
| **Local, not compressed, size ≤ threshold** | **DIRECT‑SMALL** (CopyFileExW copy) | **mmap** *(compare bytes)* | n/a | `decision: DIRECT‑SMALL | reason: size<threshold` |
| **Local, not compressed, size > threshold** | **DIRECT‑LARGE** (mmap copy) | **hash** *(on the fly)* | **Yes** only if local **NTFS**; else **No** | `decision: DIRECT‑LARGE | reason: size≥threshold`; if pre‑alloc unsupported: `info: prealloc skipped (unsupported)` |

**Global rules baked into the table:**
- **Never pre‑allocate over network**
- **Never pre‑allocate when compression is intended**
- Pre‑allocate failure is not an error -> **skip the pre‑allocate and continue** with a single info log

- **STAGED** *(chunked copy)* : source is read in chunks and written in chunks, buffered, best for network and compression copies
- **DIRECT‑SMALL** *(CopyFileExW copy)* : Windows native fast copy best for smallish local files
- **DIRECT‑LARGE** *(mmap copy)* : fast memory mapped windowed reading and writing chunks, best for large local files
- **hash** *(on the fly)* verification : source is hashed when reading to copy, no reading a second time just to hash it
- **mmap** *(compare bytes)* verification : fast memory mapped windowed read of source and target chunks and compare them

## 7) “Preview Decisions” table — recommended columns
For each file (before running the copy):
- **File** (relative path)
- **Src compressed?** (Y/N)
- **Tgt dir compressed?** (Y/N)
- **Compression intended?** (Y/N)
- **Network?** (Y/N)
- **Target FS** (NTFS/other/unknown)
- **Size**
- **Strategy** (STAGED / DIRECT‑SMALL / DIRECT‑LARGE / ABORT)
- **Verify** (`hash on the fly` / `mmap compare bytes`)
- **Pre‑alloc** (Yes/No per policy)
- **Notes** (e.g., “will attempt FSCTL_SET_COMPRESSION”, “prealloc skipped: network”, “override: FSCTL failed -> proceeding uncompressed”, “blocked: sparse source”)

---

## 8) Logging / naming (consistent & grep‑friendly)
- **Decision explainer** (INFO):
  - `decision: STAGED (network) | verify=hash on the fly`
  - `decision: STAGED (target‑compress) | verify=hash on the fly`
  - `decision: DIRECT‑SMALL | verify=mmap compare bytes | reason: size<threshold`
  - `decision: DIRECT‑LARGE | verify=hash on the fly | reason: size≥threshold`
- **Overrides** (INFO):
  - `override: FSCTL_SET_COMPRESSION failed -> proceeding uncompressed`
  - `info: prealloc skipped (network)` / `(compression intended)` / `(unsupported)`
- **Debug detail** (DEBUG only):
    - DIRECT-SMALL: verify=mmap-bytes(src:mmap)
    - DIRECT-LARGE: verify=hash(src:mmap, algo:blake3)
    - STAGED: verify=hash(src:stream, algo:blake3)

---

## 9) Acceptance examples (what you should see)
- **Local, small, normal:** `decision: DIRECT‑SMALL | verify=mmap compare bytes | reason: size<threshold`
- **Local, large, normal:** `decision: DIRECT‑LARGE | verify=hash on the fly | reason: size≥threshold` (+ optional `info: prealloc skipped` if not NTFS)
- **Local, source compressed:** `decision: STAGED (src‑compress) | verify=hash on the fly` (+ FSCTL attempt)
- **Network, any:** `decision: STAGED (network) | verify=hash on the fly` (no pre‑alloc; FSCTL only if target NTFS and compression intended)
- **Sparse source:** modal + status; no strategy chosen; row shows ABORT
